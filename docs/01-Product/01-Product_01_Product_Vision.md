# 1. Executive Summary

TaskMyScreen is an Android-first Progressive Web Application whose mission is to ensure that users never forget an important task by delivering highly personalized notifications exactly when they are needed.

TaskMyScreen is NOT a task management application.

TaskMyScreen is a notification intelligence platform.

Tasks are merely the mechanism that generates personalized reminders.

The notification experience is the product.

---

# 2. Product Mission

Help people remember what matters.

Every reminder should arrive:

- at the correct time
- with the correct context
- with the correct visual information
- with the minimum user effort

The application exists to reduce forgotten actions.

---

# 3. Product Vision

TaskMyScreen shall become the reference application for personalized scheduled reminders on Android.

Unlike traditional reminder applications, TaskMyScreen associates every reminder with visual context.

Every reminder becomes immediately recognizable.

Users should never need to remember why they created the reminder.

The application reminds them using:

- title
- description
- screenshot
- intelligent scheduling

---

# 7. Product Philosophy

TaskMyScreen follows five principles.

## Principle 1

The notification is the product.

Everything else exists to support it.

---

## Principle 2

Context beats memory.

Images communicate faster than text.

---

## Principle 3

The application should disappear until needed.

Users interact only when necessary.

---

## Principle 4

Every interaction must reduce friction.

Creating a reminder should require the minimum number of actions.

---

## Principle 5

Android users expect native behavior.

The PWA must feel indistinguishable from a native application whenever technically possible.

# 14. Competitive Differentiation

Traditional reminder applications focus on lists.

TaskMyScreen focuses on contextual memory.

Traditional reminder applications notify.

TaskMyScreen reminds intelligently.

The screenshot is the differentiating feature.

The Android notification becomes the primary interface.

---

# 15. Product Constraints

The application MUST remain a PWA.

The Android experience MUST feel native.

Notification reliability MUST always have priority over cosmetic improvements.

Business logic MUST remain platform independent.

No feature may compromise notification delivery.
